# Market data and synthetic books

The two feeds answer different questions. Nasdaq TotalView-ITCH supplies order-level activity in a continuous market. Replaying it on a fixed interval lets us examine how often Zeequent's rule reaches a price tie. Cboe Europe BXE supplies prices and volumes from an operating periodic auction. It publishes outcomes without the competing auction orders needed to recompute its price. Zhang and Ibikunle describe this market design in [The market quality effects of sub-second frequent batch auctions](https://doi.org/10.1016/j.irfa.2023.102737).

| Input or output | Use | Included in the release |
|---|---|---|
| `sample_days.csv` | Draw order and screen decisions for AAPL | Yes |
| `../results/replay_AAPL*`, `../results/generator_validation_AAPL.json` | Aggregate replay and generator statistics | Yes |
| `../examples/worked_book.csv` | Hand-worked book with an IO order | Yes |
| `daily_bars.csv`, `../realdata/databento/` | Screen inputs and licensed Nasdaq messages | No |
| `calibration_AAPL.json`, `calibration_AAPL_core.npz`, `syndata_bench/`, `../results/replay_books/` | Calibration, synthetic books and reconstructed books | Generated locally |
| `../fbadata/BXE_2020-09-01.ORAp.csv`, `../results/fba_bxe/` | Cboe feed, auction summaries and outcome books | External input and local outputs |

The bootstrap generator copies the central 21 ticks of a sampled replay book, then draws the periphery from calibrated distributions and rescales its totals. Its output can retain individual volume values from the licensed input. Uniform books generated by the Rust benchmark require no market data.

## Nasdaq replay

Run the commands below from `data/`. The pipeline uses Python, NumPy and the Databento client. Start with the shipped `sample_days.csv`. To repeat the entire screen, first supply the matching `daily_bars.csv`. Without that input, `sample_days.py` skips the price and volume checks and writes a different day list. See the [sampling design](SAMPLING_PLAN.md).

```sh
python fetch_totalview.py --symbols AAPL --days 4 --schemas mbo
python replay.py --selftest
```

The first command obtains a cost quote using `DATABENTO_API_KEY`. With an authorized account, `--execute --max-usd BUDGET` requests the files subject to the chosen budget. The four passing analysis days are 23 January, 4 May, 9 July and 20 July 2026. The published replay-book sample also uses 27 August, a screened-out comparison day. Reproducing all 32 selected books requires that fifth MBO file as well.

```sh
python replay.py --symbol AAPL --deltas 0.1,1,10,60 --dump-books 32
python calibrate.py --symbol AAPL --deltas 0.1,1,10,60
python gen_synthetic_book.py --validate
for n in 100 250 500 1000 2000; do
    python gen_synthetic_book.py --ticks "$n" --delta 1 --count 5 --seed 2027 --out syndata_bench
done
```

`--dump-books` caps the total number of exported books. The replay takes up to one example of each plateau class per day and duration. The four-day tie estimates exclude the comparison day. Calibration also excludes flagged days by default.

At each price the reconstructed book combines resting depth at interval end, displayed passive fills, and aggressor-side volume during the interval. The replay evaluates intervals containing a trade with an identified aggressor side. On a one-cent grid and a one-second interval, 3.63% of crossing batches had more than one volume-maximizing tick, averaged across the four days. Pooling the batches gives 3.79%. The bootstrap produced 4.06% in the corresponding generator run. These figures concern a counterfactual application of the rule to continuous-market flow.

## Cboe periodic auctions

With the Orange SA file for 1 September 2020 available locally:

```sh
python bxe_auctions.py ../fbadata/BXE_2020-09-01.ORAp.csv ../results/fba_bxe --books
```

There are 922 periodic update messages and 362 periodic summaries in the sample. The script associates positive indicative-price updates with the next periodic summary and matches flagged executions by timestamp. The 400 matching executions total 238,921 shares. The median size is 433.5 shares per auction. In 320 cases the first associated positive-price update is within 100 ms of the summary. This interval measures the messages observed on the feed.

For each summary the script constructs a 101-tick book centred on the published price, with the executed quantity on both sides at tick 50. All 362 books have a unique maximizing tick and zero imbalance. Together they test observed quantities, the external EUR 0.001 grid and both implementations' clearing outputs. They cannot identify unexecuted interest or the venue's tie-break.

## Passing a book to the provers

CSV rows are ordered by increasing price. `Bids++` and `Asks++` give ordinary volume at a tick. The Noir converter reads optional `IO_Bids` and `IO_Asks`. Rust's `data` command sets IO volume to zero, so only the ordinary columns are comparable through this route. All 419 market-derived benchmark inputs have zero IO. For an IO example, use Noir or the Rust order-entry workflow.

```sh
zeequent data --files book1.csv,book2.csv --kin 32 --runs 20 --csv timings.csv
bash ../zeequent-noir-standalone/prove.sh book1.csv
```

Obtaining the Databento source requires authorized access. The Cboe source file must be obtained separately.
